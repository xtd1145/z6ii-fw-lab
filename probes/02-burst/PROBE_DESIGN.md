# 连拍规格 · QEMU / 真机可执行探针设计（v2，按 P0/P3 实测修正）

日期：2026-10-29　对象：Z6 II v1.70（eg1850）　前提：主线 QEMU 已能冷启动；HMP `memsave` 可用

> **工具口径**：一律用 HMP `memsave <vaddr> <size> <file>`。QMP `pmemsave` 在本机坏（全 0），不再使用。
>
> **安全边界**：所有探针只读；P0/P1/P3/P4 只读，P2/P5 只监视 guest 写、不发起写；`memsave`/`xp` 只读；不写 NOR/分区表/卡/相机。
>
> **地址口径**：mas 运行期基址是 **0x10020000**，所有静态 VMA 在运行期 **+0x20000**。SLA 的 4K60 表有独立的运行期副本 `0x1091D58C`，不要套 mas 的 delta。
>
> **最终收口（2026-10-29）**：CAPTG 需要实际拍摄序列；仿真机无法创建。LV 就是默认 APPLV、registry 仍 53 条无 CAPTG；Movie 模式/Release mode/外接快门 G14/G15 均不可达或不触发；DX 切换 registry 0 差异。P1 启动仅 `0x1032C9C8`（SIF_5）命中 1 次。P2/P3/P5 全部改真机探针；P0/P1/P4 的仿真结果见 [P0_P3_REANALYSIS.md](P0_P3_REANALYSIS.md) §7。
> **B1 导出**：真机没有 JTAG 时，用 NP3 tone curve 块分页导出。真实格式：`NCP\0` + TLV，tag `0x0002`、len `0x242`、0x40 块头 + 514 B 数据区（257×BE16），值域 0..0x7FFF；raw 514 B/次，单调 222 B/次。见 [B1_DUMP_PLAN.md](B1_DUMP_PLAN.md)。
>
> 本设计只使用本会话的地址与本轮真实 dump；另一个会话（DX60 JPEG）的旧结论不作为判据。

## 0. 目的

回答三个问题：

1. 静止 DX 的**读出窗口**是全 DX 3936×2624，还是随 L/M/S 输出缩小？
2. CH extended / 视频的**帧周期**写在哪个结构/寄存器，5/14/30/60fps 的数值签名是什么？
3. 12-bit 与 14-bit、JPEG 与 RAW 的**读出/打包模式**在哪个字段区分？

## 1. 修正后的运行期地址表

| 结构 | 运行期 VMA | 大小/步长 | 说明 |
|---|---|---|---|
| mas 基址 | `0x10020000` | — | `memsave` 读出 `20 2f 00 ea` |
| 组件/服务名表 | `0x1244C224` | 0x18/项 | 20 B 名字 + u32 层级 ID |
| 任务描述表 | `0x1244E7A0` | 0x1C ×60 | `name[12] + type + size + 0x1000 + 0`；CAPTG=53 |
| 运行期对象注册表 | `0x1242E4D0..0x1242E820` | 0x10 ×53 | `(1,0,heap_ptr,id)`；ID 0x530–0x564 |
| 模式记录 | `0x119FF50C..0x11A0100C` | 0x480 ×6 | 稀疏状态描述，不是参数表 |
| mas 视频表 | `0x1094CF50..0x1094D028` | 12 B ×18 | 4K30/25/24、1080p120/100；**无 4K60** |
| SLA 视频表 | `0x1091D58C` | 0x20 ×16 | **4K60/50**、4K30/25/24、1080p60/50/30 |
| 尺寸表 | `0x109617B8` | 6 B ×14 | 输出几何；DX L/M/S、4K、1080 |
| SIF 名表 | `0x1078B196` | 16 B ×8 | `SIF_0..SIF_7` |
| SIF 处理表 | `0x1030E634` | 4 B ×31 | 第 12–19 项为 SIF_0..7；表内存**静态**地址 0x1030xxxx |
| SIF 运行期入口 | `0x1032CC66` 等 | — | 静态地址 +0x20000 |

### 1.1 对象注册表

- 格式 `(owner=1, 0, heap_ptr, id)`；53 条，ID `0x530..0x564`。
- 主线之前 dump 的 `0x1242E7A0` 是这张表的**尾部**（条目 45–52），不是 60 条任务描述表。
- 条目 45–52：ID `0x55e..0x564`、`0x53a` → 指针 `0xc2a4a858`、`0xc188cc18..cc48`。
- 堆在 `0xc1xxxxxx`，不在 `0x10000000..0x14000000` 的 dump 内，必须单独 `memsave`。

## 2. 探针

### P0：启动基线（已完成，地址已修正）

`memsave` 以下区域，冷启动后立即执行：

| VMA | 长度 | 文件 |
|---|---|---|
| `0x1244E7A0` | `0x690` | `task_desc.bin`（60×0x1C） |
| `0x1242E4D0` | `0x340` | `registry.bin`（53×0x10） |
| `0x119FF50C` | `0x1B00` | `mode_records.bin`（6×0x480） |
| `0x1244C224` | `0x1000` | `component_mas.bin` |
| `0x1094CF50` | `0xD8` | `video_mas.bin` |
| `0x1091D58C` | `0x200` | `video_sla.bin` |
| `0x109617B8` | `0x100` | `outsize.bin` |

> **注意**：`.local/webui/probe/mode_records.bin` 与 `probes/02-burst/mode_records.bin` 是旧地址 `0x119DF50C` 的 dump，不是修正后的 `0x119FF50C`；正确数据在 `ram_10000000.bin` 的 `0x119FF50C`。若要用独立文件，请按上表重 dump `0x119FF50C 0x1B00`。

### P1：SIF 入口 + 表读监视

**P1a 断点**（Thumb，偶数地址，运行期）：

| 通道 | 入口 VMA |
|---|---|
| SIF_0 | `0x1032CC66` |
| SIF_1 | `0x1032CBCA` |
| SIF_2 | `0x1032CB8E` |
| SIF_3 | `0x1032CB18` |
| SIF_4 | `0x1032CABE` |
| SIF_5 | `0x1032C9C8` |
| SIF_6 | `0x1032C882` |
| SIF_7 | `0x1032C77E` |

每次命中记录：

- `pc, r0, r1, r2, r3, sp, lr`；
- `mem[r0:0x80]`；
- 若 `[r0+0xC]` 在 `0x10000000..0x14000000`，dump `mem[[r0+0xC]:0x80]`；
- 若 `r1` 在 `0x10000000..0x14000000`，dump `mem[r1:0x100]`；
- 每场景最多 200 次，超出后只计数。

**P1b 表读监视**：对 `0x1030E664..0x1030E684`（表项 12–19）加读监视，记录 `pc, addr, value`。
目的：确认调度器是否读这张静态表、是否在查表后加 `+0x20000`。

> 2026-10-29 启动 trace：8 个入口只有 `0x1032C9C8` 命中 1 次，其余 7 个 0 命中。启动阶段 SIF 入口不是模式配置路径（或只初始化一个通道）；P1 必须在菜单切换/拍摄时再跑。若菜单切换后仍只有这一个入口，说明配置不经过 SIF 入口，转 CAPTG/对象路径。

### P2：模式记录写监视（真机）

**只监视 guest 写，不发起任何写。** 对 `0x119FF50C..0x11A0100C` 加写监视，记录 `timestamp, pc, addr, width, value, old_value`。

- 仿真机已收口（没有快门脚，DX 切换不创建 CAPTG），P2 仅真机。
- 注意：启动时记录里只有 3–6 个 dword（ID 0x309/0x30b/0x57b/0x57c 和小枚举），**没有宽/高/周期**；不要期待在这里直接看到参数。

### P3：对象注册表 + 堆对象（真机）

**仿真机已收口**：LV 就是默认 APPLV，registry 仍 53 条无 CAPTG；DX 切换 0 差异；Movie 模式/Release mode/外接快门 G14/G15 均不可达或不触发。**CAPTG 需要实际拍摄序列，以下只在真机执行。**

1. 实际拍摄前 dump `0x1242E4D0..0x1242E820`（53×0x10）。
2. 实际拍摄单张 / CH / CH extended 后立即 dump 同一 registry；看 CAPTG（任务索引 53）/SHUTTER（54）是否新增，预期新条目 ID 在 `0x565+`。
3. `memsave` 堆（真机）：
   - `0xc188c000`，`0x1000` → handle/descriptor 区；
   - `0xc2a40000`，`0x10000` → 整个 `0xC2A4xxxx` 对象 arena；看 `0xC2A4A858` 是否从 0 变非零。
4. 若真机拍摄后 registry/arena 仍无变化，则 CAPTG 不在可观察 RAM 路径，停止该路线。

**registry → handle → object 两级**：注册表条目指向 `0xC188CC18..cc48` 的 handle，handle 里再存对象指针（如 `0xC2A4AAB8`）。仿真机 `0xC2A49000` 全 0 是对象未初始化/服务未启动，不是地址错；真机拍摄后应能看到对象槽变非零。若仍全 0，跑一次 `xp /16x 0xC2A4A858` 检查是否是物理地址（`pmemsave` 坏，不能用）。

### P4：模式表读监视

| 表 | VMA | 长度 | 用途 |
|---|---|---|---|
| mas 视频表 | `0x1094CF50` | `0xD8` | 4K30/25/24、1080p120/100 |
| SLA 视频表 | `0x1091D58C` | `0x200` | **4K60/50**、4K30/25/24、1080p60/50/30 |
| 尺寸表 | `0x109617B8` | `0x100` | FX/DX/4K/1080 输出几何 |

记录 `timestamp, pc, table, addr, index, record_hex`。
目的：确认每个场景选中了哪一行；4K60 只在 SLA 表里，不要在 mas 表里找。

### P5：MMIO 写回退（真机）

**只监视 guest 写，不发起任何写。** 仅在 P1–P4 找不到窗口/周期时启用：

- 范围 `0x20000000..0x25000000`；
- 排除 `0x24040000..0x24047000`（GPIO）、`0x20140000..0x2014E000`（GPIO 时钟/复位）；
- 只记写，过滤值未变化；每场景前后 200 ms。

仿真机已收口，**P5 仅真机**。

## 4. 预期签名

### 4.1 宽高（u16/u32，little-endian）

`6048=0x17A0`、`4024=0x0FB8`、`3936=0x0F60`、`2624=0x0A40`、`2944=0x0B80`、`1968=0x07B0`、`1312=0x0520`、`3840=0x0F00`、`2160=0x0870`、`1920=0x0780`、`1080=0x0438`。

### 4.2 周期（µs，u32）

`5fps=200000=0x00030D40`、`10fps=100000=0x000186A0`、`14fps=71429=0x00011705`、`30fps=33333=0x00008235`、`45fps=22222=0x000056CE`、`60fps=16667=0x0000411B`。
同时搜 ns 变体（×1000）和“行数/时钟 tick”变体。

### 4.3 视频表签名

- SLA 表 `rate` 字段是 **fps×1000**：`60000=60fps`、`50000=50fps`、`30000=30fps`。
- 4K60 记录：`w=3840,h=2160,rate=60000,e9 03`（1001/1000）。
- mas 表没有 4K60，只有 4K30/25/24。

## 5. 通过标准

1. P0 完成；P3 找到 CAPTG/SHUTTER 的运行期对象或确认它们在模式切换后新增。
2. P1/P4 在菜单切换场景中至少命中一次 SIF 入口或表读，且能对上所选画幅/尺寸。
3. 真机场景 2/3/5/6（或 7）中至少三个找到随 fps 变化的字段，数值在 1/fps ±5%；5fps/14fps 比值 2.7–2.9。
4. DX M/S vs DX L 能回答“读出窗口是否随输出尺寸缩小”。
5. 14-bit 与 12-bit 至少一个字段不同，且能解释 ×1.4。
6. 全程无 Data Abort；冷启动 PASS（客体 ≥2.4 s、GPU 上传 ≥250、渲染 ≥200、HUD >30、cpu0 不在 `0x101034fc`）。

## 6. 回传格式

```
scene_<n>_<name>/
  task_desc.bin / registry.bin / mode_records.bin / component_mas.bin
  video_mas.bin / video_sla.bin / outsize.bin
  sif_hits.csv / table_reads.csv / mode_writes.csv / mmio_writes.csv
  heap_small.bin / heap_obj.bin          # 若已补 dump
  notes.txt
```

`signatures.txt` 里列出每个 dump 命中的宽/高/周期值（偏移 + 值 + 置信）。

## 7. 边界

- 不修改固件、不刷机；探针只读内存/寄存器。
- 不在 `dist/`、`.local/` 或其他会话目录写文件；本目录只写文档。
- 不把固件、K8 或 `key.json` 写进 git。
- 如果 P1–P5 在真机上也全部无命中，说明静止读出配置不在可观察的 RAM/MMIO 路径，下一步只能上 JTAG/逻辑分析仪或厂商工具。
