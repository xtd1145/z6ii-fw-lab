# Z6 II v1.70 连拍规格 · 最终版（选择 B）

日期：2026-10-29　结论：**运行期映射未取到，本轮不生成 DX45/DX30 功能补丁；交付连拍规格最终版 + 可执行探针设计。**

> 工具口径：HMP `memsave <vaddr> <size> <file>`；QMP `pmemsave` 在本机坏（全 0），不要用。
> 地址口径：mas 运行期基址 **0x10020000**（静态 VMA +0x20000）；SLA 的 4K60 表有独立运行期副本 `0x1091D58C`。
> **安全边界**：所有探针只读；P0/P1/P3/P4 只读，P2/P5 只监视 guest 写、不发起写；`memsave`/`xp` 只读；不写 NOR/分区表/卡/相机。
> **无 JTAG 的导出**：真机数据用 NP3 tone curve 块（tag `0x0002`、len `0x242`、0x40+514 B、0..0x7FFF）分页带回；raw 514 B/次，单调 222 B/次，见 [B1_DUMP_PLAN.md](B1_DUMP_PLAN.md)。

## 0. 为什么选 B

- 静态侧已经做到：目标档位锁定、物理预算、容器/K8 重签、可启动验证包。
- 静态侧没有做到：SIF/TG 的窗口、帧周期、12-bit 读出配置没有落在任何可改的静态表/常量里；任务描述表没有入口指针；模式记录只有稀疏状态 ID。
- 因此现在改任何“连拍参数”都只能靠猜；猜错会破坏读出时序或缓存，不能算安全补丁。
- 上一轮的 `deliverable/Z6_2_0170_poc_compressed.bin` 是**打包/启动验证包**（菜单标签 `Lossless COMPRESSED`），不是连拍功能补丁；它的冷启动 PASS 只证明 K8 重签链路可用，不证明任何连拍参数。

### 0.1 最终收口（2026-10-29）

**CAPTG 需要实际拍摄序列；仿真机无法创建，标真机探针。** 仿真机已排除的路径：

- LV 就是默认 APPLV，冷启动即存在（上传 300+），registry 仍 59 行、无 CAPTG → **LV 不创建 CAPTG**。
- Movie 模式切不过去（Z6 II 拍照/视频是物理拨杆）；Movie Shooting Menu 只是菜单页，不启动采集管线。
- Release mode = c/E 按钮 + 主指令拨盘，模型没有对应输入。
- 外接快门 G14/G15 在 pad 注入下不触发拍摄（G15 只产生 +28 UI 事件）。
- DX 菜单切换：registry 0 差异、arena 仅 4 B 噪声 → **DX 切换不创建 CAPTG**。

下一轮只在真机有数据时继续；不再出包、不再做仿真分析。

### 1.1 4K60 的推算（SLA `0x1091D58C`，rate=60000）

- 帧周期 = 1/60 = **16.6667 ms**（硬值，来自 `rate=60000`）。
- active pixels = 3840×2160 = 8,294,400/帧；active rate = 8,294,400 / 16.6667 ms = **497.664 MP/s**。
- 300 MHz 时钟：每帧 5,000,000 clocks；active pixels/clk = 1.659。若传感器 2 px/clk，raw 600 MP/s、blanking ≈17.1%；若 1 px/clk，300 MP/s 不够，说明 300 MHz 不是最终像素率或该字段是 PLL/参考时钟。**300 MHz 只标为候选，硬值只有 16.667 ms 和 497.7 MP/s。**
- 这是 3840×2160 的 8.29MP 视频窗口，不是全 DX 3936×2624。全 DX 60fps 需要 619.7 MP/s，超过这条 4K60 行；这解释了 4K60 为什么是裁切。
- 对目标档位：DX30 12-bit 309.8 MP/s = 4K60 视频 active 的 **62.2%**；C4 116.2 = **23.3%**；DX45 全 DX 464.8 = **93.4%**，但仍高于静止 12-bit 线 340.7（1.36×）。4K60 行不能证明“全 DX 45fps 可行”，只能证明视频路径在 8.29MP 窗口能到 497.7 MP/s。

## 2. P0/P3 已确认的事实（本轮实测）

- **mas 运行期基址 = 0x10020000**，所有静态 VMA +0x20000；主线之前四个 dump 地址都低了 0x20000。
- **任务描述表**在 `0x1244E7A0`：60×0x1C，`name[12]+type+size+0x1000+0`；CAPSEQ=52、CAPTG=53、SHUTTER=54。**没有入口指针**。
- **运行期对象注册表**在 `0x1242E4D0..0x1242E820`：53×0x10，`(1,0,heap_ptr,id)`，ID `0x530..0x564`。主线 dump 的 `0x1242E7A0` 是这张表的尾部，不是任务描述表。
- 条目 45–52：ID `0x55e..0x564`、`0x53a` → 指针 `0xc2a4a858`、`0xc188cc18..cc48`。堆在 `0xc1xxxxxx`，需单独 `memsave` 才能识别对象类型。
- **组件/服务名表**在 `0x1244C224`：0x18/项，20 B 名字 + u32 ID；`CaptureSensorService=0x0202`、`CaptureSequenceService=0x0421`、`SifDriver=0x4109`、`SifService=0x421D`。
- **SIF 处理表**在 `0x1030E634`（31×4），第 12–19 项 = SIF_0..7；表内存**静态**地址 `0x1030xxxx`，运行期代码在 `0x1032xxxx`。P1 应 hook `0x1032CC66` 等运行期入口，并对 `0x1030E664..0x1030E684` 加读监视。
- **mas 视频表** `0x1094CF50`：18×12，4K30/25/24、1080p120/100，**没有 4K60**。
- **SLA 视频表** `0x1091D58C`：16×0x20，**4K60/50**、4K30/25/24、1080p60/50/30；`rate` 字段 = fps×1000。
- **尺寸表** `0x109617B8`：6 B/项，含 FX/DX L/M/S/4K/1080；这是**输出几何**，不是读出窗口。
- **模式记录** `0x119FF50C`：6×0x480，启动时每条只有 3–6 个 dword（ID `0x309/0x30b/0x57b/0x57c` 和小枚举），**没有宽/高/周期**；不是参数表。

### 2.1 P0bis 追加（2026-10-29 主线）

- **4K60 行**：SLA `0x1091D58C` 第 0/1 条 = 3840×2160、rate=60000、clk 候选 300 MHz；4K50 在第 2/3 条。
- **P1 启动 trace**：8 个 SIF 运行期入口只有 `0x1032C9C8` 命中 1 次，其余 7 个 0 命中。说明启动时 SIF 入口不是模式配置路径（或只初始化一个通道）；P1 必须在菜单切换/拍摄时再跑。
- **0xC2A49000 全 0**：这是 0xC2A4xxxx 对象 arena；0xC188C000 有数据，是 handle/descriptor 区。`0xC188CC18` 的 8 字节条目里含 `0xC2A4AAB8` 指针，说明 registry → handle → object 是两级；对象 arena 在启动时未初始化/未启动服务。需要模式切换后再 dump。

## 4. 真机最小采集清单（仿真机已收口）

CAPTG 需要实际拍摄序列；以下只在真机执行：

1. **P0 启动基线（真机）**：dump 任务描述表 `0x1244E7A0`（0x690）、对象注册表 `0x1242E4D0`（0x350）、模式记录 `0x119FF50C`（0x1B00）、组件表 `0x1244C224`（0x1000）、mas/SLA 视频表、尺寸表。
2. **P1 SIF 入口（真机）**：hook 运行期 `0x1032CC66 / 0x1032CBCA / 0x1032CB8E / 0x1032CB18 / 0x1032CABE / 0x1032C9C8 / 0x1032C882 / 0x1032C77E`，dump `r0/r1/[r0+0xC]`；对 `0x1030E664..0x1030E684` 加读监视。**实际按快门/CH/CH extended 时跑**，不再在仿真机菜单里跑。
3. **P2 模式记录写（真机）**：`0x119FF50C..0x11A0100C`，实际拍摄单张/5fps/14fps/14-bit 时记录。
4. **P3 对象注册表 + 堆（真机）**：实际拍摄前后 dump `0x1242E4D0..0x1242E820`、`0xC2A40000 0x10000`、`0xC188CC00 0x100`；看 CAPTG（任务索引 53）/SHUTTER（54）是否新增、`0xC2A4A858` 是否变非零。
5. **P4 表读（真机）**：mas `0x1094CF50`、SLA `0x1091D58C`（4K60）、尺寸表 `0x109617B8`。
6. **P5 MMIO 写回退（真机）**：`0x20000000..0x25000000`，排除 GPIO `0x24040000..0x24047000`、`0x20140000..0x2014E000`，只记写并做场景差分。

仿真机不再执行 P2/P3/P5；LV/Movie/Release/G14/G15/DX 切换均已证明不可达或不创建 CAPTG。

## 5. 通过标准（真机）

- 实际拍摄（单张/CH/CH extended）后，CAPTG/SHUTTER 出现在 registry/arena，或明确证明它们不在可观察的 RAM 路径。
- P1 在实际拍摄时至少命中一个 SIF 入口；若始终只有启动时的 SIF_5，则配置不经过 SIF 入口。
- 场景 2/3/5/6（或 7）中至少三个能找到随 fps 变化的字段，数值在 1/fps ±5%；5fps/14fps 比值 2.7–2.9。
- DX M/S vs DX L 能回答“读出窗口是否随输出尺寸缩小”。
- 14-bit 与 12-bit 至少一个字段不同，且能解释 ×1.4。
- 真机无 Data Abort/ERR；不刷机。

## 6. 拿到数据后的补丁路径

1. 若窗口/周期在 **SIF 消息/对象字段**：改对应对象或初始化常量 → 重算模块 CRC/包 CRC → K8 重签；
2. 若在 **CAPTG 任务对象**：改模板或初始化常量 → 同样重封；
3. 若只在 **MMIO 初始化序列**：定位写该寄存器的指令/表 → 改常量或加一段等长配置；
4. 生成 DX45 C4 / DX30 12-bit 两个候选包，先 QEMU 冷启动 + 单张/5fps/目标模式，再谈真机。

## 7. 结论

- **DX45 JPEG 只有 C4（2.58MP 2×2 bin @45）成立；DX30 RAW 只有全 DX 12-bit @30 成立；14-bit 全 DX @30 否决。**
- 这两档的门槛不是物理，而是 **SIF/TG 运行期窗口/周期映射**；探针设计已按真实 dump 修正，等主线补 P0（修正地址）、P1、P3、P4 后即可进入补丁阶段。
- 本轮不生成功能补丁；上一轮的菜单标签包只作打包/启动验证。
